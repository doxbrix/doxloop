# Doxloop Docusaurus Format

Produce documentation that builds and renders through Docusaurus. Use this skill
together with `$doxloop-authoring`; that skill owns discovery, consultation,
coverage, and writing quality.

## Read before editing

1. Read `.doxloop/project.json` and confirm `generator` is `docusaurus`.
2. Read [references/project-format.md](references/project-format.md).
3. Read [references/authoring.md](references/authoring.md).
4. Inspect `docusaurus.config.js`, `sidebars.js`, existing docs, custom CSS, and
   locally defined React components before using them.

If the generator differs, stop and use its installed Doxloop format skill.

## Author native Docusaurus content

- Write docs under the configured content directory.
- Include a title and outcome-focused description in frontmatter.
- Preserve documented IDs, slugs, sidebar positions, tags, and pagination
  settings.
- Use standard Markdown and Docusaurus directives for portable content.
- Use `.mdx` and JSX only when an existing or built-in Docusaurus component is
  required.
- Import `Tabs` and `TabItem` before using them.
- Keep blank lines around Markdown nested inside JSX components.
- Use Docusaurus-relative or root-relative links that match generated routes.

Do not emit Doxbrix components such as `<Steps>`, `<CardGroup>`,
`<CodeGroup>`, `<ApiEndpoint>`, or Doxbrix `docs.json` navigation.
Docusaurus tabs use imported `<Tabs>` with `<TabItem>` children; Doxbrix
`<Tab>` children are invalid here.

## Maintain navigation

Implement the semantic top/left navigation plan from `$doxloop-authoring`.
Translate major surfaces and verified utility links into `themeConfig.navbar`
items and the left hierarchy into the configured sidebar strategy. Keep labels,
order, hierarchy, and routes aligned across navbar, sidebars, breadcrumbs, and
landing-page links; omit empty template groups.

Respect the project's sidebar strategy. For the default autogenerated sidebar,
organize pages with directories plus frontmatter such as `sidebar_position` and
`sidebar_label`. If the project uses explicit sidebar items, update
`sidebars.js` without evaluating unrelated configuration code.

## Apply captured branding

Use the identity and any confirmed external design profile gathered through
`$doxloop-authoring`, then apply the native mapping in
[references/project-format.md](references/project-format.md). Update
`src/css/custom.css`, `docusaurus.config.js`, and public assets together. Keep
Docusaurus accessibility and color-mode behavior intact; do not reproduce the
application layout around documentation content.

## Verify

Run `doxloop test`, then `npm run build`. Fix native configuration, sidebar,
MDX/JSX, and broken-link failures. Use `doxloop preview --open` for an
interactive visual check. Docusaurus preview uses the project's installed
native development server and installs missing dependencies automatically on
first run. Before `npm run build`, install dependencies with the project's
package manager if `node_modules` is missing.
