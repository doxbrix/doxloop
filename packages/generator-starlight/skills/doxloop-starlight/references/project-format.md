# Starlight project format

- Content root: `src/content/docs/`
- Astro and Starlight configuration: `astro.config.mjs`
- Content schema: `src/content.config.ts`
- Navigation: `starlight({ sidebar: [...] })`
- Required frontmatter: `title` and `description`
- Native asides: `:::note`, `:::tip`, `:::caution`, `:::danger`
- Import Starlight components from `@astrojs/starlight/components` in MDX.
- Custom styles: `src/styles/`
- Build: `npm run build`; output: `dist/`

## Navigation and routes

- Add every reader page exactly once to the configured sidebar or an intentional
  autogenerated group.
- Preserve explicit slugs and locale/version path segments.
- Keep content collection IDs unique.

## Components and presentation

- Use Starlight asides with supported types and balanced directive fences.
- Import built-in components from `@astrojs/starlight/components`.
- Keep custom tokens in shared CSS configured through Starlight.
- Preserve search, table-of-contents, focus, dark mode, and mobile navigation.

## Common failures

- MDX components fail when imports are omitted.
- Content schema rejects unsupported frontmatter.
- Duplicate slugs silently create confusing navigation before build failure.
- `.astro/` and `dist/` are generated output.
